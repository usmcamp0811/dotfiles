# Bootstrap Mechanism

## Overview

This document explains how the k3s cluster bootstrap works with ArgoCD and Vault Agent.

## Boot Sequence

### Stage 0: Pre-k3s (Vault Agent)

Before or alongside k3s service start, Vault Agent:

1. Authenticates to Vault using AppRole (role-id + secret-id)
2. Fetches bootstrap secrets from Vault
3. Renders Kubernetes Secret manifests using templates
4. Writes manifest files to `/var/lib/rancher/k3s/server/manifests/`

#### Vault Agent Templates

Location: Configured in NixOS module `fmf.services.k3s.vaultAgent.templates`

Templates render these files:

- **10-argocd-repo-secret.yaml** - Git repository credentials for ArgoCD

Example template:
```hcl
template {
  source      = "/etc/vault-agent/templates/argocd-repo-secret.tpl"
  destination = "/var/lib/rancher/k3s/server/manifests/10-argocd-repo-secret.yaml"
  perms       = "0600"
}
```

### Stage 1: k3s Boot

When k3s starts:

1. Reads all YAML files from `/var/lib/rancher/k3s/server/manifests/`
2. Applies them in lexical order (filename sorted)
3. Continues to watch directory for changes

#### Required Manifests at Boot

1. **00-argocd-install.yaml**
   - ArgoCD installation (either direct YAML or HelmChart CRD)
   - Creates argocd namespace and all ArgoCD components
   - Source: Copied from Nix package or generated

2. **10-argocd-repo-secret.yaml**
   - Secret for Git repository access
   - Must be in `argocd` namespace
   - Rendered by Vault Agent
   - Required before root app can sync

3. **20-root-app.yaml**
   - ArgoCD Application pointing to this GitOps repo
   - Generated by Nix package (Output A)
   - Points to `packages/gitops/clusters/campground`
   - Enables auto-sync with prune and selfHeal

### Stage 2: ArgoCD Initialization

ArgoCD pods start:

1. API server becomes ready
2. Application controller starts
3. Repo server authenticates to Git using the bootstrap secret
4. Root Application is processed

### Stage 3: GitOps Sync

ArgoCD syncs the root Application:

1. Fetches `packages/gitops/clusters/campground` from Git
2. Discovers all child Applications in `apps/` directory
3. Syncs each application in order (respecting dependencies)

#### Sync Order

Applications can specify sync waves for ordering:

- Wave 0: argocd-self, storage (infrastructure)
- Wave 1: external-secrets, vault-backend (secret management)
- Wave 2: metallb (networking infrastructure)
- Wave 3: traefik (ingress)

### Stage 4: Steady State

All applications are now managed by ArgoCD:

- Changes to Git trigger automatic syncs
- ArgoCD maintains desired state
- Manual kubectl changes are reverted (prune + selfHeal enabled)

## Bootstrap Secrets

### Why Bootstrap Secrets?

Bootstrap secrets are needed for resources that must exist BEFORE External Secrets Operator is running:

1. **ArgoCD Git repo credentials** - Required for ArgoCD to fetch the GitOps repository
2. (Optional) Any secrets needed by ArgoCD itself before External Secrets is deployed

### What is NOT a Bootstrap Secret

- Cloudflare API token - Managed by External Secrets after it starts
- Application secrets - Managed by External Secrets
- Database passwords - Managed by External Secrets

### Security Considerations

Bootstrap secrets:
- Are NEVER committed to Git
- Are rendered only on the k3s nodes
- Have restrictive file permissions (0600)
- Are owned by root
- Are not logged or printed

### Vault Paths Required

For bootstrap to work, these Vault paths must exist:

- `secret/campground/k3s` - Contains `node_token` field
- `secret/campground/argocd/repo` - Contains `ssh_private_key` field (for SSH)
  - Or `token` field (for HTTPS)
  - Optional: `known_hosts` field for SSH

### Template Format

Vault Agent templates use Go template syntax with Vault functions:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: private-repo
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: repository
type: Opaque
stringData:
  type: git
  url: {{ with secret "secret/campground/argocd/repo" }}{{ .Data.data.url }}{{ end }}
  sshPrivateKey: |
{{ with secret "secret/campground/argocd/repo" }}{{ .Data.data.ssh_private_key | indent 4 }}{{ end }}
```

Note: Adjust template for KV v1 vs v2 (`.Data.data` vs `.Data`)

## File Naming Convention

Files in `/var/lib/rancher/k3s/server/manifests/` are applied in lexical order.

Use numeric prefixes to control ordering:

- `00-*` - Core infrastructure (ArgoCD install)
- `10-*` - Secrets and credentials
- `20-*` - Applications (root app)
- `30-*` - (Reserved for additional bootstrap resources)

## Troubleshooting

### ArgoCD Not Starting

Check:
```bash
kubectl get pods -n argocd
kubectl logs -n argocd deployment/argocd-server
```

Verify ArgoCD install manifest was applied:
```bash
ls -la /var/lib/rancher/k3s/server/manifests/00-argocd-install.yaml
```

### Root Application Not Syncing

Check repo credentials:
```bash
kubectl get secret -n argocd private-repo -o yaml
```

Check Application status:
```bash
kubectl describe application -n argocd root
```

Check ArgoCD logs:
```bash
kubectl logs -n argocd deployment/argocd-repo-server
```

### Vault Agent Not Rendering Secrets

Check Vault Agent status:
```bash
systemctl status vault-agent-k3s.service
journalctl -u vault-agent-k3s.service -f
```

Verify templates exist:
```bash
ls -la /var/lib/rancher/k3s/server/manifests/
```

Check Vault Agent can authenticate:
```bash
# Check role-id and secret-id files exist
ls -la /var/lib/vault/$(hostname)/
```

### Bootstrap Manifests Missing

Check NixOS configuration deployed correctly:
```bash
systemctl status k3s.service
journalctl -u k3s.service | grep manifests
```

Verify Nix package outputs:
```bash
nix build .#gitops-root-app
cat result/root-app.yaml
```

## Recovery

If bootstrap fails:

1. Stop k3s: `systemctl stop k3s`
2. Clear manifests directory: `rm /var/lib/rancher/k3s/server/manifests/*`
3. Verify Vault Agent can render secrets: `systemctl restart vault-agent-k3s`
4. Verify bootstrap manifests exist: `ls -la /var/lib/rancher/k3s/server/manifests/`
5. Start k3s: `systemctl start k3s`
6. Watch logs: `journalctl -u k3s.service -f`

## Differences from Manual kubectl apply

Traditional deployment:
```bash
kubectl apply -f argocd-install.yaml
kubectl create secret -n argocd ...
kubectl apply -f root-app.yaml
```

k3s bootstrap approach:
```bash
# No manual steps - everything is declarative in NixOS config
nixos-rebuild switch
# k3s auto-applies manifests at boot
```

Benefits:
- Fully declarative
- Repeatable
- No manual intervention
- Disaster recovery is just "redeploy the node"
- Secrets come from Vault, not manual kubectl create
