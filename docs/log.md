# Update Log

## 2026-11-09
* **Host model, host link addresses**: `fmf.host.network.interfaces.<n>.link` makes a physical host's bridge network get its address, and on the primary interface the zone's gateway and DNS, from the record and the zone, so the simple path is written once. Eight Campground hosts use it; the bridges, VLANs and policy stay hand-written. `network.dns` now applies to hosts too, and the docs warn against a public resolver after the zone's own (systemd-resolved sticks to the last server that worked, which broke daly's Nix caches). Pure function `hostNetworkOf` with tests.
* **Fleet guides**: added a getting-started tutorial (FLEET-GETTING-STARTED.md), two tutorials for the two ways to use it (MicroVMs from records, and leases, DNS and port forwards from records), a runbook, copy-paste examples and a troubleshooting page, written for a downstream flake with little Nix experience. The setup, the generated files, the consumers (a plain dnsmasq and NAT gateway, the drift check) and the error cases were run in a scratch downstream flake against this repository; nothing was deployed or booted. The status paragraph of HOST-MODEL.md now mentions guest networking (4c) and points to the guides.
* **Host model, phase 4c (guest networking)**: `fmf.host.network.derive` (opt-in per MicroVM) configures a guest's own networking from its record and the zone catalogue: link by MAC, static address, the zone's gateway, no DHCP, name servers and `microvm.interfaces` for taps; `network.dns` and `interfaces.<n>.guestName` override. Pure function `guestNetworkOf` with tests. In Campground 19 VMs opted in and evaluate identically to their hand-written configuration, except the redundant `networking.defaultGateway`, which is no longer written.
* **Host model, all VMs migrated**: the 11 standby, unplaced MicroVMs (authentik, lemmy, netbird, nextcloud, topology and the k8s VMs) now take their shares and store overlay from a `storage.nix` each, so every one of the 31 VMs is derived; nothing is generated for a hypervisor for them until they are placed.
* **Host model, phase 3 complete**: the Vault VM, ermy's control-plane VM and butler's worker are derived from their records, so all 20 placed MicroVMs are. The Vault VM keeps `restartIfChanged` unset (it evaluates to false), so a deploy never seals Vault. ermy and butler also generate their tap rules and lose their `vm-k8s` globs. HOST-MODEL.md status brought up to date.

## 2026-11-08
* **Host model, phase 4 correction**: the router host's `br-lan.<id>` links are VLAN interfaces, not bridges, so the netobs VLAN taps can never join them; an attempt to make those rules apply was reverted after networkd failed three of the VM's five NICs. `fleet` now compares a hypervisor's declared links: a zone mapped to a non-bridge is an error and a hand-written rule enslaving to one is reported. The router host's zone map says `br-lan`.
* **Host model, phase 4b (generated tap rules)**: `fmf.host.hypervisor.tapRules` (opt-in per hypervisor) makes `fleet` write one entry per tap of each derived guest into `microvms.nix`, to be turned into an exact networkd rule that sorts before the hand-written `vm-*` globs.
* **Host model, phase 4a (network attachment, model and checks)**: added `fmf.host.network.interfaces.<n>.id` (a MicroVM interface's name on the hypervisor) and `fmf.host.hypervisor.networks.<zone>` (bridge or macvtap per zone). `lib.fmf.fleet` now also extracts each machine's guest interfaces, networkd rules and configured addresses, errors on attachments that cannot work, and warns where records and machines disagree, including which bridge each tap really joins (first matching .network file). No machine changes; in Campground it found the monitoring VM's four VLAN taps on the LAN bridge.
* **Host model, phase 3 groundwork**: measured the real MicroVM fleet (20 VMs, 7 hypervisors) and changed the derivation to match it: `nixStore` (persistent, volatile, none), `standardShares.rootPassword` and `.vaultAgent`, `storage.<name>.owner` and `.group`, `placement.hostDirectories` (managed, external), the `rw-store` share and `vm-stores` directories, and a fixed share order instead of preserving five hand-written ones. Pure functions `sharesOf`, `overlayOf` and `directoriesOf` are exported for the guest side. HOST-MODEL.md has a Phase 3 ground truth section. Nothing in Campground uses it yet.
* **Host model, phase 3 conversion path**: added `fmf.host.derive` (per VM, default off), `storage.<n>.createDirectory`, the guest-side module that sets `microvm.shares` and the store overlay from the record, and `microvms.nix` written and checked by `fleet` for the hypervisor side (VM flags, directories, start ordering). Verified on one real VM: evaluated shares equal the hand-written set and the hypervisor's other tmpfiles and ordering are unchanged.

## 2026-11-07
* **Vault runbook and phase 3 status**: added VAULT-RUNBOOK.md (the model, health checks, adding a host, changing access, narrowing or removing a broad policy, replacing and retiring a role, rotating credentials, converging, rules and troubleshooting) and a status table in VAULT-APPROLES.md. In Campground the broad `campground` policy is now off every declared role except three with no host to derive a policy from; retiring roles are declared inert (`token_policies = []`) because pruning is off. Not yet deployed.
* **Host model spec (draft)**: added HOST-MODEL.md, a specification for one `fmf.host` record per machine (interfaces and VLAN zones, lifecycle, MicroVM placement and storage, boot order, DNS, exposure, Vault, topology) and a fleet function that derives leases, DNS, port forwards, Vault roles, hypervisor hosting and boot ordering from it. Specification only; nothing is implemented.
* **Host model, phase 0**: added the `fmf.host` / `fmf.network.zones` options (modules/nixos/system/host) and `lib.fmf.fleet` with tests. Declares data only; no consumers yet. Verified against Campground with seven pilot records (results in HOST-MODEL.md).
* **Host model, phase 1 import**: Campground now has an `fmf.host` record for all 44 hosts, generated from the lease files and each host's evaluated configuration and checked against the existing leases, placement, port forwards, DNS and Vault data. Added `dhcpRange` to zones, the DNS rule that the bare host name is the primary address, and the in-pool warning; a standby MicroVM may be unplaced.
* **Host model, phase 1 consumers**: added the `fleet` command (`packages/scripts/fleet`) and `lib.fmf.fleet.render`; Campground's router leases, AdGuard names and host port forwards are now generated from the `fmf.host` records, with device leases kept in their own files and merged in. `fleet.mk` takes `deviceLeases` for DNS and clash checks; DNS names are generated lower-case; `vault-access` reads the generated leases.
* **Circuit Breaker**: the sync units no longer use systemd's default start limit (`StartLimitIntervalSec = 0`). They throttle themselves, and the limit made the end-to-end test depend on how fast the machine was (`start-limit-hit` in the git-driven sync steps).
